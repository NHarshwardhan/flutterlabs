02

Dialogs & bottom sheets

Three overlay patterns: a blocking dialog, a modal sheet that dims the page, and a persistent sheet that lives behind the app.

A — AlertDialog

Use it for a decision or a confirmation. It blocks the screen until an action is tapped.

B — Modal bottom sheet

Rises from the bottom with a scrim behind it. Grab the data straight from state.

C — Persistent bottom sheet

Owned by the Scaffold, not by a route. That is why it needs the GlobalKey<ScaffoldState>.

What happens

Same state, different surface

The sheet is a new route with its own BuildContext — note the (_) in the builder. Tapping the scrim, dragging down, or Navigator.pop closes it.

!
Height is fixed

height: 250 clips long content. For real forms use isScrollControlled: true and let the sheet size itself.

i
Who owns the sheet?

showModalBottomSheet builds a route, so Navigator.pop(context) closes it. ScaffoldState.showBottomSheet attaches to the scaffold, so you close it with the returned PersistentBottomSheetController or by tapping the scrim.

×
Null check on the key

_key.currentState! is null if the scaffold has not been built yet. Calling this from initState() crashes. Trigger it from a button, or guard with if (_key.currentState != null).

What happens

Permission, then position, then map

The screen shows a spinner while userPosition is null. As soon as the position arrives, setState swaps the spinner for a GoogleMap centred on the coordinates with a red marker.

i
Emulator tip

In Android Studio use Extended controls → Location and send a point, otherwise the GPS can take a minute to answer.

Permission valueWhat to do
whileInUseAllowed while the app is open. Carry on.
alwaysAllowed in the background. Carry on.
deniedNot answered yet or refused once — call requestPermission().

i
Why Future<Position>?

An async function that returns Future.error(...) on one path and a value on another can be inferred as Future<dynamic>. Annotating it keeps the compiler honest and makes await return a real Position.

×
Unhandled exception

deniedForever throws from determinePosition(), and nothing catches it — the red screen appears. Wrap the call in try/catch and show a message with a "Open settings" button.

04

Create the Firebase project

Console first, packages second, configure last. Skipping the order is what produces "No Firebase App '[DEFAULT]' has been created".

Console

Create a project

Name it health-app-day4. Analytics is optional — skip it to keep setup short.

console.firebase.google.com
Product

Authentication

Build → Authentication → Sign-in method → enable Email/Password. Nothing else is needed today.

Database

Two databases

Create a Realtime Database (test mode) and a Cloud Firestore (test mode) in the same project.

  1. Open the console and click Add project. Give it a name, accept the defaults.
  2. Add an Android app inside the project. The package name must match applicationId in android/app/build.gradle.kts.
  3. Add an iOS app as well if you are on a Mac — the bundle id is in Xcode.
  4. Install the FlutterFire CLI: dart pub global activate flutterfire_cli, then run flutterfire configure in the project root.
  5. Pick the platforms when asked. It writes lib/firebase_options.dart and drops the native config files in place.
  6. Enable Email/Password in Authentication, and create both databases in test mode.
  7. Stop and start the app once the config files are in.
Console project→Register app→flutterfire configure→pub get→Firebase.initializeApp()→Run
After editing pubspecflutter pub get
i
What flutterfire configure actually does

It creates a Firebase app for each platform, downloads google-services.json (Android) and GoogleService-Info.plist (iOS), and generates firebase_options.dart. That is why you no longer edit build.gradle by hand for Firebase.

!
Two project names that must agree

The Android package name in the console, the applicationId in Gradle and the app you run must all be identical. One character off and Firebase initialises to nothing, silently.

×
No Firebase App '[DEFAULT]' has been created

You called FirebaseAuth.instance before Firebase.initializeApp(). Add the two lines at the top of main() from the next step — and keep WidgetsFlutterBinding.ensureInitialized() before them.

What happens

One stream drives both screens

authStateChanges() emits a User on login and null on logout. The StreamBuilder rebuilds, and the whole navigation problem disappears — no pushReplacement needed.

i
Signup pops back

After createUserWithEmailAndPassword Firebase signs the user in automatically. The stream would already swap screens, so Navigator.pop is only there to clear the signup route.

CallEffect
signInWithEmailAndPasswordSigns an existing user in. Throws FirebaseAuthException on failure.
createUserWithEmailAndPasswordCreates the account and signs in. Fails if the email already exists.
signOut()Clears the session; the stream emits null.
authStateChanges()Stream of User? for the whole app lifetime.
currentUserThe signed-in user right now, or null. Used for the uid.
!
Case matters

The session notes write Navigator.push(Context, ...) with a capital C. That is the BuildContext type, not the variable — it will not compile. Use context.

i
Reset loading

On success the screen is replaced, so leaving loading = true is harmless. On failure it must go back to false, otherwise the spinner spins forever — that is the setState inside catch.

▶
Try it

Realtime Database

One number, saved under the user's uid, updating on every device at once.

9:41▮▮▮
Home⏻
Today's Steps3000
👣
Realtime Database
What happens

Write once, read everywhere

set(newSteps) replaces the value at that path. The onValue listener on every open device fires, so the number jumps by 1000 without any refresh button.

i
Why uid in the path?

Each account gets its own branch: users/<uid>/health/steps. The security rules can then allow a user to touch only their own node.

Where the number lives

health-app-day4
└─ users
   └─ Kx3f...9Qm   ← uid
      └─ health
         └─ steps: 3000

Security rules — test mode

{
  "rules": {
    "users": {
      "$uid": {
        ".read": "auth != null && auth.uid === $uid",
        ".write": "auth != null && auth.uid === $uid"
      }
    }
  }
}
!
The listener never stops

onValue.listen(...) returns a subscription. Store it in a StreamSubscription field and call cancel() in dispose(), otherwise the callback can hit a dead setState.

×
Permission denied

Test-mode rules expire after 30 days. If writes suddenly fail, check the Rules tab — the date usually explains it. Publish the rules above with your own uid check.

▶
Try it

Run the app on two emulators with the same account and tap the FAB on one. The other updates live. Then use update({"steps": 0, "updatedAt": ServerValue.timestamp}) and look at the tree in the console.

Firestore rules — per user

rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /health/{uid}/{doc=**} {
      allow read, write:
        if request.auth != null
        && request.auth.uid == uid;
    }
  }
}
!
orderBy skips documents

A document with no timestamp field is silently left out of the ordered query. Write it on every entry — including test data added by hand in the console.

i
serverTimestamp is pending at first

Locally it is null until the server replies. If you need to display it immediately, use DateTime.now() or listen again after the write completes.

A signed release bundle, then an upload to the Play Console. The full reference lives at docs.flutter.dev/deployment/android.

Signing, versioning, R8 shrinking and the app bundle format — kept current with each Flutter release.

Google Play Console

One-time $25 developer account. Start with an internal testing track — no review wait for invited testers.

play.google.com/console
  1. Brand the app. Set android:label in the manifest and replace the launcher icon — the default Flutter logo cannot ship.
  2. Bump the version in pubspec.yaml: version: 1.0.0+1. The part after + is the version code the store uses.
  3. Create an upload keystore with keytool and keep the file and the passwords somewhere safe.
  4. Point Gradle at it through a key.properties file that is not committed.
  5. Build the bundle. flutter build appbundle writes app-release.aab.
  6. Test the release build on a real device. Release uses different signing and R8 shrinking — bugs hide there.
  7. Upload to the Play Console, fill the store listing, run internal testing, then promote.

Challenges

Each one extends the app you just built. No challenge needs a new concept.

01 · FORM Validate before you submit

Wrap the fields in a Form with a GlobalKey<FormState>. Require a name of at least three characters and reject a sugar level below 70. Show the errors inline instead of opening the dialog.

Hint TextFormField + validator, then _formKey.currentState!.validate().

02 · SHEETS Save from the summary

Add a "Confirm" button inside the modal sheet that writes the form values to Firestore, closes the sheet, and shows a SnackBar on the form screen.

Hint Call Navigator.pop(sheetContext) before the SnackBar, or use the parent context for the messenger.

03 · MAPS Distance to the clinic

Place a fixed marker at a clinic, then print the distance in kilometres between the user and the clinic using Geolocator.distanceBetween().

Hint The result is metres — divide by 1000 and format to one decimal.

04 · AUTH Friendly error messages

Replace e.message with your own strings for user-not-found, wrong-password, invalid-email and weak-password. Fall back to a generic message.

Hint e.code is the key of the map; e.message is for the log.

05 · DATA Read the record back

Show today's saved record on the Home screen above the list: total steps, average sleep and the number of entries. Compute all three from the same stream.

Hint One StreamBuilder, then reduce over snapshot.data!.docs.

06 · SHIP A signed test build

Change the app label and icon, build a signed .aab, install the release APK on a phone, and prove the debug banner is gone.

Hint flutter build apk --release, then adb install -r build/app/outputs/flutter-apk/app-release.apk.

A fresh account can sign up, submit the form, see its own map position, save a record and see it in the list — with no red screens, no stuck spinners, and no data leaking between two accounts.

Errors you will meet again

No Firebase App '[DEFAULT]' has been created

Firebase.initializeApp() did not run, or ran after the first Firebase call. Add it at the top of main(), after ensureInitialized().

PlatformException (sign_in_failed)

The email/password provider is disabled, or the SHA-1 fingerprint is missing from the Firebase Android app. Enable the provider, then re-download the config.

PERMISSION_DENIED: Missing or insufficient permissions

Firestore or RTDB rules. Test mode expires after 30 days; write rules that compare request.auth.uid with the path.

Location services are disabled

getCurrentPosition() throws before any permission dialog if GPS is off. Check Geolocator.isLocationServiceEnabled() and prompt the user.

setState() called after dispose()

An async callback finished after the screen was popped. Guard with if (!mounted) return; before setState.

The class 'X' is abstract and can't be instantiated

Left over from Day 1: you created an object from an abstract class. Create the child instead.
