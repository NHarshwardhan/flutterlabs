What happens

Six ways to tap

Book and Pay Fees are elevated buttons — the primary action. Details is outlined, for a secondary choice. Cancel is a text button, the quietest option. The phone icon is an IconButton, and the three dots open a PopupMenuButton.

i
Nested Padding

The body has two Padding widgets of 16, so the content is inset by 32 on every side. It is redundant, but harmless — remove one and the card moves closer to the edges.

WidgetUse it for
ElevatedButtonThe main action on a screen. Filled surface with a shadow.
OutlinedButtonAn alternative action of similar weight, without the fill.
TextButtonLow-emphasis actions: cancel, skip, learn more.
IconButtonA single icon with a tap target. Always give it a tooltip or label in real apps.
FloatingActionButtonOne prominent, screen-level action pinned above the content.
PopupMenuButtonOverflow actions in the app bar. value is returned to onSelected.
DropdownButtonPick one value from a list. The current value is stored in state.
▶
Try it

Open the menu and choose View Profile — nothing happens yet because the if body is empty. That is the hook for the challenge. Then change the dropdown to Dentist and watch the label update.

!
Why value!?

onChanged receives a nullable String?, but the dropdown can never select null with this setup. The ! asserts that. If you later allow a null entry, remove the ! and handle the null case.

02

Navigation: push and pop

Two screens, one stack. Navigator.push puts a route on top; Navigator.pop takes it off.

Split the UI into a home screen and an appointment screen. Each has its own Scaffold and AppBar; the back arrow appears automatically on the second one.

What happens

The navigator is a stack of routes

MaterialPageRoute builds the new screen and slides it in. The old screen stays alive underneath, which is why Go Back returns instantly. Navigator.pop(context) removes the top route; the system back gesture does exactly the same thing.

i
Names in the builder

builder: (content) => AppointmentScreen() — the parameter name content is arbitrary. Most code calls it context, but it shadows the outer one, so avoid that habit.

▶
Try it

Tap Book Appointment, then use the emulator's back gesture instead of Go Back. Same result: one route pops. Then push the appointment screen twice and press back twice — count the stack.

Send a doctor into the next screen, then send a result back to the screen that opened it.

Arguments go in through the constructor. A result comes back through Navigator.pop(context, value), which resolves the Future returned by Navigator.push.

LineMeaning
AppointmentScreen(doctor: "Dr.Smith")Passes an argument into the new screen through its constructor.
await Navigator.push(...)Waits for that route to be popped, then gives you its result.
Navigator.pop(context, value)Closes the route and completes the Future with value.

i
Why not const?

AppointmentScreen has a non-final field (doctor), so its constructor cannot be const. Making the field final would allow a const constructor and is the better habit.

Hero: animate a widget across routes

Give the same tag to two widgets on two screens and Flutter flies one into the other.

The home screen gets a small avatar; the appointment screen gets a large one. Both are wrapped in Hero with the tag "doctorPic". When the route changes, Flutter matches the tags and animates position and size.

i
Tags must match — and be unique

Two heroes with the same tag on one screen is an error. The tag only has to be unique per screen, because Flutter matches the outgoing and incoming trees.

!
Needs a MaterialApp

The flight is drawn by the navigator, so Hero only animates inside a MaterialApp (or CupertinoApp). On a bare runApp(Center(...)) it has nowhere to fly.

What happens

The controller is the browser

WebViewController owns the page. The cascade (..) configures it: JavaScript on, then a URL loaded. WebViewWidget is just the view that renders whatever the controller is showing.

!
Rebuilds create a new controller

This controller is built inside build(), so any rebuild reloads the page. In a real app, create it once in a StatefulWidget's initState() and reuse it.

!
Stop and start the app

Adding a plugin changes the native build. Hot reload cannot pick it up: press q, then run flutter run again. If the page stays blank, check the emulator's internet connection and that compileSdkVersion is 34 or higher.

Put Home, Doctors and Profile behind a persistent bottom bar — and keep each tab's state with IndexedStack.

The shell owns the Scaffold, the app bar and the navigation. The three tab screens become plain widgets with no Scaffold of their own.

What happens

One Scaffold, three bodies

_currentIndex decides which child of IndexedStack is visible. Tapping an item calls setState, and the bar highlights the new index. Because all three children stay mounted, a tab keeps its scroll position and state while you switch away.

i
Why no Scaffold inside?

HomeScreen, DoctorScreen and ProfileScreen sit inside the shell's body. A second Scaffold would add a second app bar and break the layout.

i
IndexedStack vs body: children[index]

Swapping the child rebuilds it and loses its state. IndexedStack keeps every child alive and paints only the selected one — the standard choice for bottom navigation.

▶
Try it

Change the app bar colour to Colors.indigo. Then replace _currentIndex with a literal 1 — the bar and the body disagree, which shows why both read the same field.

What happens

The controller does the bookkeeping

DefaultTabController(length: 3) creates a controller above the Scaffold. TabBar reads it for the indicator, TabBarView reads it for the page index. Tap a tab or swipe the body — both stay in sync.

i
Keep the lengths equal

length, the number of Tab widgets and the number of TabBarView children must all match. A mismatch throws at runtime.

BottomNavigationBar

Lives at the bottom, one destination per item.

Best for 3–5 top-level destinations the user switches between constantly. You manage the index yourself.

TabBar

Lives in the app bar, swipeable body.

Best for a smaller set of related views on the same screen. DefaultTabController manages the index.

▶

What happens

Three slots, one row

ListTile gives you leading, title, subtitle and trailing without any manual layout. map(...).toList() turns the data into a list of widgets, and ListView scrolls when they overflow.

i
Why the !?

A Map<String, String> lookup returns String? because the key might be missing. The ! asserts that every map has the key. A missing key becomes a runtime error — keep the data shape consistent.

!
Column vs ListView

The previous screen used a Column, which cannot scroll. A fourth doctor would overflow the bottom of the screen. ListView is the scrollable replacement — and it only builds the rows that are visible.

▶
Try it

Add a drawer: to the Scaffold and Flutter gives you the hamburger icon, the slide animation and the scrim for free.

Nothing needs to be wrapped and no state is required. A non-null drawer makes the app bar grow an icon; tapping it slides the panel over the body. The header is a UserAccountsDrawerHeader, the rows are ordinary ListTiles.

Where does the button come from?

Scaffold checks whether drawer is set and, if so, inserts a leading IconButton that calls openDrawer(). Adding a leading: of your own replaces it; call Scaffold.of(context).openDrawer() to keep the behaviour.

What happens

Columns first, then rows

Every DataColumn is a header; every DataRow must supply one DataCell per column, in the same order. The table measures its columns and aligns the text, which is why the numbers line up without any manual padding.

!
Three columns is the safe limit

DataTable does not scroll sideways on its own. If a cell is wide or the phone is narrow you get the yellow-and-black overflow stripe. Wrap the table in SingleChildScrollView(scrollDirection: Axis.horizontal).

SelectableText: let the user copy

One word changes the behaviour: Text becomes SelectableText and long-press starts a selection.

Appointment details are exactly the kind of thing people copy into a message. Replacing the home text is a one-line swap — the parameters style and textAlign are the same as Text.

What happens

Selection handles appear

A long-press selects the word under your finger and shows the native drag handles and the Copy toolbar. Tap elsewhere to clear it. Nothing else on the screen changes: same size, same weight, same alignment.

i
When to use it

Read-only text the user may want to reuse: booking references, addresses, codes, phone numbers. Do not use it for buttons or labels — a tap would start a selection instead of the action.

!
It is not a text field

SelectableText cannot be edited. If the user needs to change the value, that is TextField (or TextFormField) with a controller.

Stack: put the badge on the avatar

Layer a small green dot over a big circle. Stack overlays children, Positioned pins one to a corner.

The profile tab finally gets a real avatar. The photo is the first child of the Stack and defines its size; the online dot is the second child, pinned with Positioned and given a white border so it reads as a cut-out.

9:41▮▮▮
Health App
JS
Avatar + online dot
What happens

Later children paint on top

The Stack sizes itself to the largest non-positioned child — the 160 px avatar. Positioned(bottom: 10, right: 10) then places the 20 px dot relative to the avatar's box, so it always sits in the lower-right corner.

i
Why the white border?

Border.all(color: Colors.white, width: 2) separates the green dot from the photo, the same trick messaging apps use. Without it the dot disappears into a dark image.

!
Positioned needs a Stack

Using Positioned anywhere else throws Incorrect use of ParentDataWidget. It is only valid as a direct child of Stack (or IndexedStack in some cases).

▶
Try it

Change bottom: 10 to top: 0, left: 0 and watch the dot jump to the top-left. Then add a third child — a Text inside a Positioned at the centre — to label the photo.

Challenges

Six extensions that reuse today's widgets. None of them needs a new package.

01 · MENUS Make the overflow menu work

In MyButtonDemo, handle all three items. View Profile pushes ProfileScreen; the other two show a SnackBar naming the action.

Hint The switch happens in onSelected. Push with Navigator.push; show feedback with ScaffoldMessenger.of(context).

02 · STATE Show the booked appointment on Home

Lift the appointment string into HealthApp (or HealthHome), pass it to HomeScreen, and update it when the booking screen returns a result.

Hint The result arrives from the awaited Navigator.push in onPressed. Call setState there — the shell is the stateful widget, not HomeScreen.

03 · HERO Fly the real photo

Replace the "S" initials with the same NetworkImage on both screens. Keep one CircleAvatar at radius 40 and the other at 60, both inside Hero(tag: "doctorPic").

Hint Both tags must match exactly. If the image flickers mid-flight, check that both use the same URL so it is already in the cache.

04 · WEBVIEW A loading bar

Show a LinearProgressIndicator while the page loads. Hide it once loading finishes. Reach for NavigationDelegate and set state.

Hint onPageStarted → true, onPageFinished → false. Move the controller into initState() so a rebuild does not reload the page.

05 · DRAWER Menu items that switch tabs

Make Doctors in the drawer jump to the Doctors tab, and Profile to Profile. Close the drawer first.

Hint DefaultTabController hides its controller. Replace it with a TabController field created in initState, then call _controller.animateTo(index).

06 · STACK A status that changes

Turn the online dot into a status indicator: green for available, amber for busy. Tapping the avatar toggles it.

Hint ProfileScreen becomes stateful. Wrap the avatar in GestureDetector or InkWell, keep a bool, and pick the colour with a ternary.
i
Definition of done

All four tabs open without a red screen, the drawer closes when you pick an item, Open Website loads a real page, the appointment result appears in a SnackBar, and the avatar badge sits exactly on the photo. Run flutter analyze — no warnings, no unused imports.

Errors you will meet again

There are multiple heroes that share the same tag

Two Hero widgets with the same tag are mounted on one route. Make each tag unique per screen — the pair across two routes is the only allowed duplicate.

use_build_context_synchronously

You used context after an await. Guard it with if (!context.mounted) return; before touching the navigator or a messenger.

A RenderFlex overflowed by N pixels

A Column, Row or DataTable is wider than its parent. Scroll it, wrap the flexible child in Expanded, or reduce the columns.

MissingPluginException

The native side of a plugin is not in the running build. Hot reload cannot add it: press q and run flutter run again. A flutter clean helps if it persists.

The argument type 'String?' can't be assigned to 'String'

A Map lookup returns a nullable value. Use doctor["name"]! once you are sure the key exists, or handle null explicitly.

requires Android SDK 34 / compileSdkVersion

webview_flutter needs a recent SDK. Set compileSdkVersion 34 in android/app/build.gradle, or compileSdk = 34 in build.gradle.kts, then rebuild.

!
One last check

Every screen should survive a rotation and a hot restart. If a tab resets when you switch away, you are swapping the child instead of using IndexedStack. If the WebView reloads on every rebuild, its controller is being created inside build().
